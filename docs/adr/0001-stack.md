# ADR 0001: Expo (CNG) or bare React Native

Status: accepted
Date: 2026-11-03
Decision: expo

> `Decision:` is `expo` or `bare`. `Status:` becomes `accepted` only after the user agrees.

## Context

Mes Ouvertures (PRD v0.1.0, approved) is a portrait, offline chess opening trainer: an 8x8 board with ~32 pieces,
tap-tap and drag input, green arrows, a pasted-PGN importer, a spaced-repetition scheduler and local persistence.
No Firebase (`firebase: none`), no network, no sensor beyond vibration. Built locally on Windows, APK sideloaded.

Libraries the PRD implies, all checked against Expo SDK 57 prebuild + New Architecture:

| Need | Library | Expo / New Arch |
|---|---|---|
| Chess rules (legal moves, SAN, check, castling, en passant, promotion) | `chess.js` 1.x (BSD-2-Clause, pure TypeScript, no native code) | yes (plain JS) |
| Board, pieces (cburnett SVG), arrows, highlights | `react-native-svg` via `npx expo install` | yes (Expo-supported module) |
| Drag, tap, move animation (~150 ms) | `react-native-gesture-handler` 2.x + `react-native-reanimated` 4.x | yes (Reanimated 4 requires New Arch, the Expo default) |
| Move / capture / error / success sounds | `expo-audio` (+ `expo-asset`), `recordAudioAndroid: false` | yes |
| Vibration on error | `expo-haptics` | yes |
| Persistence (openings, line states, settings) | `@react-native-async-storage/async-storage`, versioned keys | yes |
| Phone language | `expo-localization` (factory overlay) | yes |
| PGN paste | a multi-line `TextInput` (system paste), no clipboard module | n/a |

Rendering: **React Native Views + react-native-svg + Reanimated/Gesture Handler**. At most 32 pieces and a few
arrows, far below the ~100 animated components where Skia would be needed; no Skia (saves ~10 MB of APK).
PGN parsing, repertoire tree, scheduler and session queue are pure TypeScript in `src/game/`, `chess.js` used
only for legality and SAN normalisation.

## Criteria

| Criterion | Weight | Expo (CNG + prebuild) | Bare React Native | Notes |
|---|---|---|---|---|
| All required libraries work with Expo prebuild / config plugins | high | yes, all listed above | yes | no library needs a custom plugin |
| Need to hand-edit native Android code continuously | high | not needed | possible but useless | portrait lock and permissions go through `app.json` |
| Custom native module (Kotlin/C++) needed | medium | no | no | |
| Upgrade effort over time | medium | low: bump SDK, `npx expo install --fix` | higher: Upgrade Helper diffs | |
| Build simplicity on this machine (local Gradle) | medium | proven by the factory's Expo apps (`build-apk.mjs`) | proven too | |
| Firebase setup effort | low | n/a (`firebase: none`) | n/a | |

## Decision

Expo with Continuous Native Generation, built locally with prebuild + Gradle:
1. Every library the PRD needs is an Expo module or Expo-supported, nothing native to write.
2. Upgrades stay cheap (SDK bump) and the factory's build, verify and release scripts are proven on Expo.
3. A future backend is plain `fetch` to a configurable URL and does not change this choice.

## Consequences

- Easy: one `app.json` for portrait, permissions (`AD_ID` removed, no RECORD_AUDIO), name per language.
- Harder: any native tweak has to be a config plugin (none foreseen).
- `android/` is generated by `npx expo prebuild` and git-ignored; native changes go through config plugins.
- Third-party assets: cburnett pieces are CC BY-SA 3.0, credited in « À propos » and the README; `chess.js` licence
  listed in the README.

## Alternatives considered

- Bare React Native: no criterion of `stack-decision.md` applies (no impossible library, no custom native module,
  no wish for manual control); it only adds upgrade cost.
- Skia canvas board: needless for 32 pieces, +~10 MB APK.
- Writing chess rules by hand (as in the PWA's move validator): `chess.js` is small, tested and handles SAN
  disambiguation, en passant and promotion, which the importer needs to be exact.
